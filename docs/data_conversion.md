# データの変換と正規化の決まり

公表データを Parquet に変換するときの決まりです。決まりをそろえておくと、誰が変換しても同じ表ができ、指標の結果を比べられます。

- 登録済みのデータを使うだけなら、「1. 取得と変換の流れ」と「4. データセットごとの説明」を読んでください。
- 新しいデータセットを足すときは、全部を読んでください。

## 1. 取得と変換の流れ

```bash
chiiki-od list                                  # 登録済みのデータセットと指標
chiiki-od fetch <id>                            # 公表元から取得して data/raw/<id>/ に置く
chiiki-od fetch <id> --from-dir <フォルダ>       # 手元に保存した公表ファイルから取り込む
chiiki-od convert <id>                          # data/processed/<id>.parquet に変換する
```

`--from-dir` では、公表元のファイル名のまま置いたフォルダを指定します。ファイル名が公表元の URL と違うデータは、`datasets/<id>.yaml` の `local_name` に名前が書いてあります。

変換すると、次のファイルができます。

| ファイル | 中身 | リポジトリに入れるか |
|---|---|---|
| `data/raw/<id>/<key>.<拡張子>` | 元ファイルの写し | 入れない |
| `data/processed/<id>.parquet` | 変換後の表 | 入れない |
| `data/processed/<id>__<名前>.parquet` | 本体のほかの表（記号が入っていたセルの一覧 `__flags` など） | 入れない |
| `codebooks/<id>.csv` | 変換後の列名と元の見出しの対応、記号や欠損の件数（専用パーサーが作るもの） | 入れる |
| `manifests/<id>.json` | 取得元の URL、元ファイルの SHA-256、取得日時、変換後の行数と列 | 入れる |

Parquet のメタデータにも、出典表記・元ファイルのハッシュ値・変換日時が入ります。元ファイルが同じなら、誰が変換しても同じ表になります。`fetch`・`convert` をやり直して manifest の時刻だけが変わったときは、コミットしません。

### 手作業でダウンロードするデータ

公表ページが案内ページで、ファイルを直接取れないデータがあります（定義に `manual_download: true`）。公表ページから保存し、`--from-dir` で取り込みます。

| データセット | 入手元 | 保存するファイル |
|---|---|---|
| `medical_facility_survey_r7` | e-Stat（医療施設調査） | `n0001.csv`・`n0002.csv` |
| `population_jumin_r7` | e-Stat（住民基本台帳に基づく人口） | `2504ssnen.xlsx` |
| `kouseikyoku_todokede_ika_r8` | 各地方厚生（支）局の「届出受理医療機関名簿」 | 医科のファイル（厚生局ごとに名前が違う。定義の `local_name`） |

ほかのデータセットは、`chiiki-od fetch <id>` で公表元から取得できます。公表元が URL を変えたときは、定義の `url` を直します。

## 2. 正規化の決まり

### 読み込み

- **全列を文字列で読みます。** コードや事業所番号の先頭の0を落とさないためです。数値にするのは、定義の `type` が `int`・`float` の列だけです。数値の桁区切りのカンマは除きます。
- 空のセルと空白だけのセルは欠損にします。
- 見出しが2段以上の Excel は「上段_下段」の形でつなぎます。
- それでも読めない表は、専用パーサーを書きます。たとえば、見出しの位置が決まっていない表、合計行や注記行が混ざる表、シートが複数ある表です（`src/chiiki_od/parsers.py`）。

### 列名

- 変換後の列名は、英字の小文字・数字・`_` だけにします（例：`hospital_beds`）。元の見出しは定義の `source` とコードブックに残ります。
- 地域や医療機関を表す列は、どのデータセットでも同じ名前にします。

| 列名 | 中身 |
|---|---|
| `pref_code`・`pref_name` | 都道府県コード（2桁の文字列）・名前 |
| `municipality_code`・`municipality_name` | 市区町村コード・名前。政令市は区。桁数（5桁か6桁か）は定義の `description` に書く |
| `secondary_area_code`・`secondary_area_name` | 二次医療圏（4桁＝都道府県2桁＋2桁） |
| `koso_kuiki_code`・`koso_kuiki_name` | 構想区域（4桁） |
| `od_facility_code`・`facility_name` | オープンデータ医療機関コード・医療機関名（病床機能報告・外来機能報告） |
| `medical_code_ika`・`medical_code_shika` | 医療機関コード（医科・歯科）10桁＝都道府県2桁＋「1」（医科）または「3」（歯科）＋7桁 |
| `office_number`・`office_name` | 介護保険事業所番号（10桁）・事業所名 |
| `lat`・`lon` | 緯度・経度 |

- 列の多い表（病床機能報告など）は、表の種類を表す1文字と、元の列の位置（3桁）で名前を付けます（例：`w137`＝病棟票の137列目）。意味はコードブックで引きます。

### 欠損と記号

- **記号は欠損（NA）にし、0にはしません。** 「`*`」（1〜9件のため秘匿）、「`-`」（未報告・非該当）、「未報告又はデータ不備」などです。0にすると、少ない件数や無回答が「0件」に化けます。
- 元の記号は捨てず、`__flags` の表（行・列・記号）か、コードブックの件数に残します。
- 調査で「空欄は0とみなす」とされた項目は、0と無回答を区別できません。どの列がそうかを、コードブックの `zero_if_blank` などで分かるようにし、`docs/datasets/` に書きます。
- 秘匿された値の補い（「*」に1〜9のどれを入れるかなど）は、変換ではしません。指標の計算の中で行い、その方法を指標カードの `caveats` に書きます。

### コードと地域

- **市区町村コードは5桁の文字列で比べます。** 6桁（検査数字付き）のコードは `chiiki_od.codes.to_code5` で5桁にします（検査数字も確かめます）。登録済みのデータには5桁と6桁が混ざっています。新しく足すデータは、できれば変換の段階で5桁にそろえてください（住民基本台帳・医療施設調査と同じ）。
- 政令市は区のコードのまま持ちます。市にまとめるときは `codes.ward_to_city` を使います。
- 下3桁が000のコードは都道府県そのものを表します（`codes.is_prefecture_level`）。市区町村の集計に混ぜないでください。
- 構想区域・二次医療圏への割り当ては、自分で作らず、`reference/` の共通対応表を使います（[reference/README.md](../reference/README.md)）。
  - 区域は見直されるので、どの時点の表かを確かめます。`koso_kuiki.csv` は令和7年度、`secondary_medical_area_2023.csv` は令和5年12月31日時点です。
- 市町村合併の旧コードの対応表（`municipality_mergers.csv`）は、まだ作っていません。過去の年のデータを足すときは注意してください。

### 時点と出典

- ファイルごとに `as_of`（データの時点）を書きます。1つのデータに複数の時点が混ざるとき（厚生局によって時点が違う名簿など）は、時点を列に持たせます。
- `license.attribution` に出典表記の例を書きます。成果物には「〜を加工して作成」と書きます（[docs/attribution.md](attribution.md)）。
- 元データそのものはリポジトリに入れません。取得元と元ファイルのハッシュ値は `manifests/` に残ります。

### 検算

- 変換したら、公表されている合計と照らします。たとえば、都道府県計が市区町村の合計と一致するか、全国計が公表値と一致するかです。
- 専用パーサーでは、検算を処理の中に組み込みます（630調査、医療施設調査がその例です）。
- 確かめた行数・コードの数・重複の有無を `verified_note` に書きます。

## 3. 新しいデータセットを足す

1. **Issue で相談します。** 同じデータがもう登録されていないか、どの時点のファイルを使うかを先に決めます。
2. **定義を書きます。** [datasets/_template.yaml](../datasets/_template.yaml) をコピーして `datasets/<id>.yaml` を作ります。`id` はファイル名と同じにし、時点を末尾に付けます（`_r7` など）。
3. **ファイルを取り込みます。** `chiiki-od fetch <id>`（または `--from-dir`）で取り込み、実際の見出しを確かめて `columns` を書きます。想定した列がないと、`convert` が実際の列名を並べて止まります。
4. **専用パーサーを書きます（必要なとき）。** 1行の見出しで読めない表は、`src/chiiki_od/parsers.py` に関数を足し、定義の `parser` に名前を書きます。関数の返り値の形は、`parsers.py` の冒頭に書いてあります。
5. **変換して検算します。** `chiiki-od convert <id>` のあと、上の「検算」を行います。確かめたら `verified: true` にし、`verified_note` を書き直します。
6. **使い方を書きます。** `docs/datasets/<名前>.md` に、表の形、記号の意味、時点、使うときの注意、簡単な集計の例を書きます。サイトの質問窓口は、この文書も根拠にして答えます。
7. **テストを足します。** 専用パーサーを書いたときは、合成サンプル（`tests/fixtures/`）で、変換と検算のテストを足します。
8. **確かめて PR を送ります。** `chiiki-od check`・`pytest`・`ruff check .` を通してから、プルリクエストを送ります。
