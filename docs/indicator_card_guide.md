# 指標カードの書き方

指標カードは、指標の定義と、**作成者がその指標で何を見ようとしたか**を残すための文書です。サイトの解説チャットボットは、カードに書かれたことだけを根拠に答えます。カードに書かれていない質問には「作成者の説明はありません」と答えるので、答えられなかった質問はカードを書き足すきっかけになります。

形式は `schemas/indicator_card.schema.json` で決まっていて、`chiiki-od check` で検証されます。

## 各欄の書き方

| 欄 | 書くこと |
|---|---|
| `name` | 日本語の正式名。単位まで含める（「65歳以上人口1万人あたり訪問介護事業所数」） |
| `unit_of_analysis` / `unit_note` | 集計単位。政令市・特別区・構想区域をどう扱うか |
| `numerator` / `denominator` | 何を数え、何で割るか。重複の除き方や除外条件も。データの時点 |
| `datasets` | 分子・分母のほかに使うデータセットのid（任意）。結果のファイルの「使ったデータ」に、ここに書いたものも出る |
| `intent` | この指標で何を見たいのか。地域医療構想のどの議論に使うつもりか |
| `why_this_denominator` | なぜこの分母か。検討して選ばなかった候補と、その理由 |
| `interpretation` | 値が大きい・小さいときに言えること、言えないこと |
| `caveats` | データの限界、時点のずれ、小地域での不安定さ、コードの扱い |
| `alternatives` | 関連する別の指標と、どういうときにそちらを使うか |
| `output` | 計算結果の表の読み方（サイトの「結果を見る」で使う） |

## よい `intent` と、足りない `intent`

足りない例：

> 訪問介護事業所の数を人口で割った指標。

これは計算式を言い直しているだけで、なぜ作ったのかが分かりません。

よい例：

> 在宅で暮らす高齢者を支える訪問介護の拠点が、地域によってどれくらい偏っているかを、全国で同じ方法で比べるための入口の指標。新たな地域医療構想で在宅医療・介護の受け皿を議論するとき、まず「拠点が少ない地域」を見つける目的で作った。供給量そのものではなく、拠点の分布を見ている。

「何を見たいか」「どの議論で使うか」「何を見ていないか」の3点があると、読む人も、チャットボットも、指標の使いどころを間違えにくくなります。

## よい `why_this_denominator`

分母の選び方は、研究者によって考えが分かれやすいところです。選んだ理由だけでなく、**選ばなかった候補とその理由**を書いてください。

> 需要に最も近いのは要介護認定者数だが、認定率そのものに地域差があり、それが指標に混ざる。まずは人口を分母にして拠点の分布を比べ、認定者数を分母にした版は別の指標として並べる方針にした。

別の分母のほうがよいと考える人は、その指標を別に登録し、互いに `alternatives` で参照します。

## `caveats` に書くことの例

- 時点のずれ（分子は6月末、分母は1月1日 など）
- 小地域での不安定さ（人口の少ない町村では1件の差で値が大きく動く）
- コードの扱い（政令市の区、都道府県コードの行、市町村合併）
- 欠損の扱い（「未報告又はデータ不備」「－」をゼロにしていないこと）
- 定義の変更（年度によって報告項目や選択肢が変わる）

## `output`：結果の表の読み方

サイトの「結果を見る」は、この欄を使って表・グラフ・CSVを出します。計算スクリプトが返す表の**すべての列**を `columns` に書きます（書き漏れがあると `chiiki-od results` がエラーにします）。

```yaml
output:
  area_code: municipality_code5     # 地域コードの列（先頭2桁が都道府県コード、文字列）
  area_name: municipality_name      # 地域名の列
  value: offices_per_10k_65plus     # 指標の値の列
  numerator: offices                # 分子の列（都道府県計・全国計に使う）
  denominator: pop_65plus           # 分母の列
  scale: 10000                      # 分子÷分母に掛ける数
  digits: 3                         # 値を表示する小数点以下の桁数
  unit: 事業所／65歳以上人口1万人
  columns:
    - {name: municipality_code5, label: 市区町村コード}
    - {name: municipality_name, label: 市区町村名}
    - {name: offices, label: 訪問介護事業所数, unit: 事業所}
    - {name: pop_65plus, label: 65歳以上人口, unit: 人}
    - {name: offices_per_10k_65plus, label: 65歳以上人口1万人あたり事業所数, unit: 事業所／1万人}
```

- `numerator`・`denominator`・`scale` を書くと、都道府県計と全国計（分子の合計 ÷ 分母の合計 × scale）を出します。割合や人口あたりの指標では書いてください。書かない場合は中央値だけを出します。
- `label` はCSVの見出しにもなります。単位は `unit` に分けて書きます。

### 推移を持つ指標（`time`）

年度ごとの値を1つの表に縦に並べた指標では、時点の列を `time` に書きます。

```yaml
output:
  area_code: koso_kuiki_code
  ...
  time: fiscal_year        # 時点の列（"FY2020" などの文字列。並べ替えた順が時点の順になるように）
  time_stat: mean          # 任意。推移のグラフの全国・都道府県の線（pooled＝計、median＝中央値、mean＝平均）
```

- 表・地図・棒グラフ・都道府県計は、**最新の時点**の行で作ります。CSV にはすべての時点の行が入ります。
- 「結果を見る」に推移の折れ線グラフが出ます（全国、選んだ都道府県、強調した地域を3つまで）。
- `time_stat` を省くと、`numerator`・`denominator` があれば計、なければ中央値です。病院別の該当項目数のように、計がない値の平均を見たいときは `mean` にします。

### 地図とチャットからの切り替え

`output` があると、「結果を見る」に塗り分け地図も出ます。地図に載せるには、次の2つが必要です。

- **集計単位に地図の境界があること**：境界があるのは、`unit_of_analysis` が `municipality`（市区町村。政令市は市でも区でもよい）、`designated_city_ward`（政令市の区）、`koso_kuiki`（構想区域）、`prefecture`（都道府県）のときです。`secondary_medical_area`（二次医療圏）・`facility`・`ward_unit` は境界がまだないため、地図は出ません（グラフと表は出ます）。二次医療圏は構想区域とコードの多くが同じですが、境界が違う地域があるので、構想区域の地図では代用しません。
- **地域コードが境界のコードと一致すること**：境界は、令和8年1月1日の市区町村と、令和7年度病床機能報告の構想区域（`reference/koso_kuiki.csv`）です。コードは市区町村が5桁、構想区域が4桁、都道府県が2桁の文字列です。古い時点のデータで合併前のコードが残っていると、その地域は地図で「値なし」になります。結果のコードのうち境界にあるものが9割に満たないと、地図そのものを出しません。`chiiki-od check` が、地図に出ない地域とその理由を注意として示します。

色の区切りは、`chiiki-od results` が計算した全国の四分位をそのまま使うので、カードに書くことはありません。

質問窓口に「熊本市を表示して」のように書くと、`area_name` の列の名前と照合して地域を選びます。地域名は都道府県の中で区別できる名前にしてください（政令市の区は「中央区」ではなく「札幌市中央区」）。都道府県名やコードは名前に含めないでください（「熊本県熊本市」「43100 熊本市」では照合できません）。
